# Liftly — Future Work (postponed)

These features are intentionally out of V1. They are recorded so they are not lost, not so they get built early.

| Feature | Why postponed | Revisit when |
|---|---|---|
| Home workouts | Gym-only scope for V1 | After beta shows demand |
| Nutrition tracking and guidance | Separate product area; needs its own safety review | Later phase, as planned |
| Coach chat (free-form questions) | Keeps Claude's role narrow and testable | After debriefs are validated |
| Wearables | Not needed to validate progression | After core loop is stable |
| Apple Health / Google Health Connect | Integration adds scope and privacy review | After beta |
| Subscriptions and payments | Free beta first | When monetization is decided |
| Social features, leaderboards, sharing | Not needed for the beta | After retention is proven |
| Form analysis from video | Large technical and safety scope | Much later |
| Advanced programming (periodization, blocks) | Beginner scope only | When advanced users are a target |
| Strength and powerlifting modes | Different goal and engine | When a strength goal is added |
| Native iOS and Android apps | Web app first | After web app validation |
| Graduating users to harder programs | Could be V1.5 | After beta data |
| Weekly review (Claude) | Not in frozen spec | Decide before build |
| Custom routines and user-created exercises | Engine needs a fixed library | After library is stable |
| Claude-written plans | Engine must remain deterministic | Not planned |
| Cardio tracking | Outside muscle-building focus | Later |
| Languages and other markets; lbs | India/kg only for V1 | When expanding |
| Injury / rehabilitation modes | Out of scope; medical boundary | Not planned without a qualified partner |

## Rules for adding a feature

1. Don't add a postponed feature during V1 development.
2. A new feature needs a numbered spec revision and a reason.
3. Any feature that touches progression, pain, or Claude's role needs a safety review first.
